================================================================================
 GRACE Robot — ESP32 Firmware Parameters (Torque Control)
================================================================================

Updated: Firmware switched from speed-command to torque-command mode.
Protocol:  ROS → ESP32:  "tL<val> tR<val>\n"     e.g. "tL120 tR-115\n"
           ESP32 → ROS:  comma-separated sensor string (200 Hz)

================================================================================
 COMMAND PARAMETERS (ROS → ESP32 → Hoverboard STM32)
================================================================================

Parameter         Range          Units              Description
----------        -----------    -----------------  ------------------------------------------
targetTorqueL     [-1000,1000]   firmware units     Left wheel torque command (FOC q-axis
                                 (dimensionless)    current reference). Positive = forward.
targetTorqueR     [-1000,1000]   firmware units     Right wheel torque command. Positive = forward.
                                 (dimensionless)

  NOTE: Firmware units map to the hoverboard FOC current setpoint.
        Physical torque:  τ [N·m] = Kt * firmware_cmd
        Kt must be calibrated on your motor. See section at bottom.

  b40500p       → battery 40500 mV (40.5V)
  t0350p        → temperature 350 deci-°C (35.0°C)
  TL0120p       → target torque left = +120 firmware units
  Lm0050p       → measured speed left = +50 RPM
  TR0115n       → target torque right = -115 firmware units
  Rm0048n       → measured speed right = -48 RPM
  cL01200p      → DC current left = +1200 mA
  cR01150p      → DC current right = +1150 mA
  qL00800p      → iq (q-axis current) left = +800 mA
  qR00750p      → iq (q-axis current) right = +750 mA
  dL00010p      → id (d-axis current) left = +10 mA
  dR00015p      → id (d-axis current) right = +15 mA
  aL18000p      → electrical angle left = 18000 (180.00°)
  aR09000p      → electrical angle right = 9000 (90.00°)
  I11           → IMU1 OK
  ax1...gz1     → IMU1 raw accel/gyro data
  I21           → IMU2 OK
  ax2...gz2     → IMU2 raw accel/gyro data

================================================================================
 CALIBRATING Kt (Firmware Units → Physical Torque)
================================================================================

The firmware torque command is a dimensionless value [-1000, 1000] that maps to
the FOC q-axis current reference in the hoverboard STM32. To use the LQR
controller (which works in N·m), you need the conversion factor:

    τ_physical [N·m] = Kt × firmware_command

Method 1 — From motor constants:
    Kt = Km × (I_max / CMD_MAX)
    where Km = motor torque constant [N·m/A]
          I_max = max phase current at CMD_MAX=1000
    Typical hoverboard motor: Km ≈ 0.1–0.3 N·m/A, I_max ≈ 10–20A
    → Kt ≈ 0.001–0.006 N·m per firmware unit (per motor)

Method 2 — Empirical (recommended):
    1. Place robot on blocks (wheels free-spinning)
    2. Send constant torque command u_fw (e.g., 200) to one wheel
    3. Read steady-state iq from feedback (in mA)
    4. Measure wheel angular acceleration α from speed feedback
    5. τ = Jw_total × α  (Jw_total includes wheel + hub motor rotor)
    6. Kt = τ / u_fw

Method 3 — From iq feedback:
    τ = Km × iq
    Kt = Km × (iq / u_fw)    using measured iq for a given u_fw

Default estimate (NEEDS CALIBRATION):
    Kt ≈ 0.004 N·m per firmware unit per motor
    For both motors: Kt_total = 2 × Kt ≈ 0.008 N·m per firmware unit
